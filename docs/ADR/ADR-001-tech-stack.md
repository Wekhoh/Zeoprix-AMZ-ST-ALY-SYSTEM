# ADR-001: 技术栈选择

**状态**: 已接受
**日期**: 2026-01-10
**决策者**: Jack Huang

---

## 背景

为AMZ搜索词分析系统选择合适的技术栈。目标用户是亚马逊北美站FBA中国卖家，他们可能不具备深厚的编程背景，需要一个易于部署和使用的解决方案。

---

## 决策

### 选择的技术栈

| 层级 | 选择 | 版本 |
|------|------|------|
| 后端语言 | Python | 3.10+ |
| Web框架 | Streamlit | ≥1.40 |
| 数据库 | SQLite | 内置 |
| AI服务 | Google Gemini | API |
| 数据处理 | Pandas | ≥2.2 |

---

## 考虑的选项

### 选项1: Python + Streamlit（已选择）

**优点**:
- Python是数据处理的首选语言
- Streamlit学习曲线极低，专为数据应用设计
- 无需分离前后端，开发效率高
- 目标环境为 Python 3.10+，无需额外配置

**缺点**:
- Streamlit的定制化能力有限
- 大规模用户不适用（本项目是单用户本地应用，不影响）

### 选项2: Python + Flask/FastAPI + React

**优点**:
- 更灵活的前端定制
- 更适合生产级部署

**缺点**:
- 开发复杂度高
- 需要前端开发技能
- 对于MVP来说过度设计

### 选项3: Node.js + React

**优点**:
- 前后端统一语言
- 丰富的UI组件库

**缺点**:
- Python的数据处理生态更成熟
- 用户环境已有Python

---

## 决策理由

1. **用户环境**: 目标环境为 Python 3.10+，无需额外配置
2. **开发效率**: Streamlit允许快速迭代，纯Python开发
3. **学习成本**: 目标用户是卖家而非开发者，Streamlit的使用门槛最低
4. **数据处理**: Python + Pandas是CSV/Excel处理的黄金标准
5. **本地运行**: 单用户本地应用，Streamlit完全胜任

---

## 影响

- 所有后端逻辑使用Python编写
- UI开发使用Streamlit组件
- 无需构建API端点
- 部署方式：本地运行 `streamlit run src/app.py`
