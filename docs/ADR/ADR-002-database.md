# ADR-002: 数据库选择

**状态**: 已接受
**日期**: 2026-01-10
**决策者**: Jack Huang

---

## 背景

需要选择一个数据库来存储：
- 产品档案信息
- 广告活动数据
- 搜索词明细
- 规则配置及版本历史
- 分析结果

预计数据规模：单次分析1万行以内，总存储量不超过100MB。

---

## 决策

**选择SQLite**作为主数据库。

---

## 考虑的选项

### 选项1: SQLite（已选择）

**优点**:
- 零配置：无需安装数据库服务
- 便携性：整个数据库是一个文件
- Python内置支持
- 性能足够：10万行级别查询毫秒级
- 支持JSON字段（存储规则条件）

**缺点**:
- 不支持并发写入（本项目单用户，不影响）
- 无网络访问（本项目本地运行，不需要）

### 选项2: PostgreSQL

**优点**:
- 企业级功能
- 优秀的JSON支持
- 强大的查询优化器

**缺点**:
- 需要安装和配置服务
- 对于卖家用户来说门槛过高
- 本项目数据量无需此级别数据库

### 选项3: MySQL

**优点**:
- 广泛使用
- 社区支持好

**缺点**:
- 需要安装服务
- JSON支持不如PostgreSQL
- 同样过度设计

### 选项4: 纯文件存储（CSV/JSON）

**优点**:
- 最简单
- 无需学习SQL

**缺点**:
- 查询能力弱
- 无法高效处理多维聚合
- 数据一致性难保证

---

## 决策理由

1. **零运维**: 用户只需运行Python脚本，无需管理数据库服务
2. **便携性**: 数据库文件可以备份、迁移
3. **性能足够**: 1万行数据的聚合查询在SQLite中是毫秒级
4. **Python生态**: sqlite3是Python标准库
5. **JSON支持**: SQLite 3.9+支持json_extract函数

---

## 技术细节

### 数据库路径
```
data/db/app.db
```

### 连接方式
```python
import sqlite3
conn = sqlite3.connect("data/db/app.db")
```

### JSON字段使用
```sql
-- 查询规则条件中的阈值
SELECT * FROM rules
WHERE json_extract(conditions, '$.spend_threshold') > 10;
```

---

## 影响

- 所有数据存储在单个文件中
- 使用Python sqlite3模块操作
- 需要在应用启动时初始化表结构
- .gitignore中排除*.db文件
